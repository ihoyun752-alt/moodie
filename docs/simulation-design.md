# 얼굴 메이크업 시뮬레이션 설계

- 작성일: 2026-11-02 (v5 승인 설계)
- 관련 문서: `docs/product-database-design.md` 10절(데이터), `docs/recommendation-engine-plan.md` 7절(추천), `docs/product-color-draft.md` 5절(측정 색 기록)
- 목표: 사용자가 고른 무드와 추천 제품 셰이드를 **같은 얼굴 이미지**에 자연스럽게 적용해 보여 줍니다. HEX 색을 단순히 덮지 않고, 원래 피부·입술의 명암을 살려 실제 메이크업처럼 보이게 합니다.

## 1. 기준 얼굴 이미지

- `assets/moods/`의 얼굴 이미지 7장은 이미 메이크업이 되어 있어 **기준 이미지로 쓰지 않습니다.** 그 위에 색을 더하면 원래 색과 섞여 셰이드 색이 틀어지기 때문입니다.
- **맨얼굴 기준 이미지는 담당자가 AI 이미지 생성으로 따로 만들어 전달합니다.** 전달받기 전에는 얼굴 이미지를 만들거나 다른 이미지로 대신하지 않습니다.

| 조건 | 내용 |
|---|---|
| 인물 | AI로 만든 가상의 인물 (실제 인물 아님) |
| 구도 | 정면. 눈, 코, 입이 명확하게 보임 |
| 메이크업 | 거의 없는 자연스러운 맨얼굴. 진한 입술 색, 블러셔, 아이섀도 없음 |
| 조명 | 균일하고 색 왜곡이 적음 |
| 사용 범위 | 모든 무드에 같은 얼굴 1장을 씀 |

- 저장 위치(제안): `assets/simulation/base-face.png`. 받은 원본은 수정하지 않고, SHA-256 해시를 `docs/image-credits.md`에 기록합니다.
- 화면에는 "AI 생성 이미지 · 실제 인물 아님"을 표시합니다.

## 2. 얼굴 영역 마스크

| 영역 (`area`) | 설명 |
|---|---|
| `lip` | 입술 |
| `cheek-l`, `cheek-r` | 왼쪽·오른쪽 볼 |
| `eyelid-l`, `eyelid-r` | 왼쪽·오른쪽 눈꺼풀 (쌍꺼풀 선과 눈썹 사이) |
| `skin` | 얼굴 피부 전체 (눈, 눈썹, 입술, 머리카락 제외) |

- 마스크는 기준 이미지와 같은 크기의 **흑백 PNG**입니다. 흰 부분에만 색을 적용하고, 회색은 그만큼 약하게 적용합니다(경계 흐림).
- 저장 위치(제안): `assets/simulation/masks/<area>.png`
- `dev/edit-moods.py`의 눈 주변 보호 좌표는 **기존 얼굴 기준**입니다. 새 기준 이미지에 그대로 맞는지 반드시 확인한 뒤에만 참고합니다.
- 마스크가 기준 이미지와 맞는지 검수한 날짜를 기록합니다.

**`data/simulation-masks.csv`**

| 컬럼 | 의미 |
|---|---|
| `mask_id` | 마스크 번호 |
| `base_image` | 기준 이미지 경로 |
| `base_image_sha256` | 기준 이미지 해시 (이미지가 바뀌면 마스크를 다시 검수) |
| `area` | 위 표의 영역 |

## 3. 시뮬레이션 색 (`data/simulation-colors.csv`)

| 컬럼 | 의미 |
|---|---|
| `product_id` | 셰이드 ID. `products.csv`에 있어야 함 |
| `area` | 적용 영역. 카테고리와 맞아야 함 (lip → `lip`, cheek → `cheek-l`·`cheek-r`, eye → `eyelid-l`·`eyelid-r`, base → `skin`) |
| `sim_hex` | 표시용 색. 공식 HEX가 아니라 측정한 추정값일 수 있음 |
| `color_source` | `official` / `swatch-measured` / `mixed` |
| `source_image` | 색을 측정한 이미지 (주소나 파일 이름) |
| `measure_box` | 측정 위치 (예: `(550,2528)-(710,2564)`) |
| `blend_mode` | 혼합 방식 (4절) |
| `opacity` | 적용 강도 0~1 |
| `gloss` | 광택 0~1 (0 = 매트) |
| `shimmer` | 펄·반짝임 0~1 |
| `gradient` | 아이섀도 그라데이션 방향 (예: `lash-to-brow`), 다른 부위는 빈 칸 |
| `status` | `approved` / `pending` |
| `approved_by`, `approved_at` | 승인한 사람·날짜 |

- **`status = approved`인 줄만 얼굴에 적용합니다.**
- 측정 근거의 원문과 이미지 출처는 `data/evidence.csv`(`domain = color`)에도 남깁니다.

## 4. 색 적용 방식 (브라우저 캔버스)

- **원본 보존:** 기준 이미지 파일은 절대 수정하지 않습니다. 브라우저 캔버스에만 그리고, "원본 보기 / 적용 보기"를 전환할 수 있게 합니다.
- **적용 순서:** 베이스 → 치크 → 아이 → 립. 영역마다 마스크가 따로 있어 서로 번지지 않습니다.

| 부위 | 혼합 방식 | 초기 `opacity` | 광택·펄 |
|---|---|---|---|
| 립 | 원래 입술의 명암과 주름을 살리는 `color` 혼합(색상·채도만 바꿈) + 약한 `multiply`로 깊이 표현 | 0.6~0.85 (매트는 높게, 틴트·밤은 낮게) | `gloss`가 크면 원래 밝은 반사광 픽셀을 덮지 않고 살림 |
| 치크 | 부드러운 원형 그라데이션 마스크 + `soft-light` 또는 `multiply` | 0.15~0.35 | `shimmer`가 있으면 아주 약한 `screen` 반짝임 층 |
| 아이 | 쌍꺼풀 선 쪽이 진하고 눈썹 쪽으로 옅어지는 그라데이션 + `multiply` | 0.3~0.6 | 펄 셰이드는 미세한 반짝임 층 |
| 베이스 | ~~`skin` 마스크 + 약한 `soft-light`~~ → 11절: 브라우저에서 만든 베이스 마스크 + 픽셀 비율 합성(`shade`) | 0.4 | 마무리감별 광 보존 (매트 0.55 · 세미매트 0.7 · 그 밖 0.85) |

- 위 수치는 **실제 발색값이 아닌 초기 시뮬레이션 설정**입니다. 화면을 보면서 조정합니다.

## 5. 연결과 검증

- 흐름: 추천 페이지에서 고른 `product_id`(`moodie.selection`) → `simulation-colors.csv`에서 `status = approved`인 같은 `product_id` 찾기 → 해당 `area` 마스크에 적용
- 연결 검사
  - `product_id`가 `products.csv`에 있음
  - `area`가 그 제품의 카테고리와 맞음
  - 마스크의 `base_image_sha256`이 현재 기준 이미지와 같음
- 결과 화면에 적용한 색의 칩, 셰이드명, "표시용 색 (측정 추정값)" 문구를 함께 보여 줍니다.

## 6. 예외 처리

| 상황 | 처리 |
|---|---|
| 고른 셰이드에 승인된 색이 없음 | 그 부위는 **칠하지 않고** "이 셰이드는 색상 확인 전이라 적용하지 않았어요"라고 표시. 비슷한 색이나 기본 색으로 대신하지 않음 |
| 기준 이미지가 아직 없음 | 시뮬레이션 영역을 숨기고 "얼굴 적용 준비 중"이라고 안내. 무드 이미지로 대신하지 않음 |
| 마스크가 없거나 검수되지 않음 | 그 부위는 적용하지 않음 |
| 마스크의 해시가 현재 기준 이미지와 다름 | 적용하지 않고 콘솔에 오류 기록 |
| 캔버스를 쓸 수 없는 브라우저 | 원본 이미지와 색 칩만 보여 줌 |

## 8. 구현 기록 (2026-11-02)

- 기준 이미지: `assets/simulation/base-face.png` (출처·가공은 `docs/image-credits.md` "메이크업 시뮬레이션 기준 얼굴").
- 마스크: `assets/simulation/masks/*.png` 6장, `data/simulation-masks.csv`에 해시와 함께 등록. 얼굴 인식 라이브러리 없이(Pillow만) 이 사진 한 장에 맞춰 만들었으므로 다른 사진에는 쓸 수 없습니다.
- 코드: `js/simulation.js` (결과 요약 화면 `result.html`에서 호출). 외부 AI·API는 쓰지 않습니다.
- 혼합 (초기 설정, 미승인. `simulation-colors.csv`의 `blend_mode`·`opacity`가 채워지면 그 값을 씀)
  - 립: `shade` = 픽셀 밝기 비율은 유지하고 입술 평균 밝기를 제품 색에 맞추는 픽셀 단위 합성. 립스틱 0.85, 그 밖 0.7. (`color` 혼합은 진한 립을 너무 밝게 표현해 바꿈). 밝고 채도가 낮은 반사광은 제품 색을 덜 입혀 살리고, 마스크 경계는 1px 흐림.
  - 아이: `multiply` 0.85, 마스크 세로 농도 0.4→1 (눈썹 쪽 옅게, 속눈썹 쪽 진하게). 눈꺼풀 영역은 속눈썹 그림자 때문에 `shade`가 오히려 밝게 만들어 제외
  - 치크: `soft-light` 0.3, 베이스: `soft-light` 0.1 (현재 승인 색이 없어 실제로는 적용되지 않음)
- 화면: 메이크업 전·후 비교, 부위별 확대(베이스·아이섀도우·치크·립), 부위마다 적용 여부와 표시용 색 표시.

- 공식 조사 자료의 칸별 측정 참고값 10개는 `data/palette-colors.csv`에 `status=reference`로 기록했습니다. 결과 화면에는 **팔레트 구성 10칸 · 확인된 개별 색**으로 표시합니다.

### 9.3 `MD-0032-02` 팔레트

- 공식 `color_note`는 없고, 공식 조사 자료에서 칸 이름 10개만 확인됩니다.

### 9.4 치크

- 치크 마스크(`cheek-l`, `cheek-r`)는 등록되어 있지만, 승인된 치크 `sim_hex`가 아직 없습니다.
- 따라서 현재는 치크를 선택해도 양쪽 볼에 색이 적용되지 않고, 결과 화면·부위별 확대에 "색상 검수 전 · 적용 안 함"이 표시됩니다.
- `data/color-approval-candidates.csv`에 치크 9개(색상 설명 있음)와 `MD-0013-02`(설명 없음, `hold`)를 승인 후보로 기록했습니다. 모두 `no-hex`·`pending`이라 적용 대상이 아닙니다.
- 적용 조건: 공식 발색 이미지에서 측정한 값 또는 담당자가 승인한 HEX를 `simulation-colors.csv`에 `status=approved`로 추가한 뒤 `cheek-l`·`cheek-r` 두 줄을 등록합니다.

### 9.5 결과 화면 일관성

- "메이크업 전" 캔버스와 "추천 제품으로 완성한 메이크업" 캔버스는 같은 기준 이미지에서 시작합니다.

## 10. 립 광택·아이섀도 영역 분할 (2026-11-02)

색 값(`sim_hex`)과 승인 상태는 바꾸지 않았습니다. 바뀐 것은 **이미 승인된 색을 얼굴에 칠하는 방식**뿐입니다. 아래 수치는 모두 화면을 보며 정한 미승인 초기값이며, 실제 발색 측정값이 아닙니다.

### 10.1 립 제형별 광택

| `subcategory` | 광택(`gloss`) | 의미 |
|---|---|---|
| `lipstick` | 0.3 | 매트. 원래 입술 반사광을 대부분 덮음 |
| `tint` | 0.75 | 반사광 대부분 유지 |
| `lip-balm` | 0.85 | 반사광 거의 유지 |
| `gloss` | 0.95 | 반사광 유지 |
| 그 밖 | 0.7 | |

- `simulation-colors.csv`의 `gloss` 칸이 채워져 있으면 그 값을 우선 씁니다(지금은 모두 빈 칸).
- 입술 안에서 원래 밝은 반사광 픽셀만 `gloss` 비율만큼 덜 칠합니다. 입술 밖 픽셀은 바뀌지 않습니다.

### 10.2 아이섀도 영역 마스크 8개 (MK-0007~MK-0014)

기존 `eyelid-l.png`, `eyelid-r.png`를 읽기만 해서 새로 만든 파생 마스크입니다(기존 마스크는 그대로). 눈마다 4개씩 있습니다.

| 영역 | 위치 |
|---|---|
| `lid` | 눈두덩 중앙~속눈썹 쪽 |
| `crease` | 위쪽 음영 띠 (중앙~눈꼬리) |
| `outer` | 눈꼬리 쪽 |
| `inner` | 눈 앞머리 쪽 |

### 10.3 팔레트 칸 역할 → 영역

`palette-colors.csv`에서 `status = approved`인 칸만 칠합니다. 역할(`tone_role`)에 따라 영역과 혼합 방식이 정해지고, 아래 순서대로 덧칠합니다.

| 순서 | 역할 | 영역 | 혼합 · 강도 |
|---|---|---|---|
| 1 | `base` | 눈꺼풀 전체 | multiply 0.35 (눈썹 쪽으로 옅게) |
| 2 | `mid` | `lid` | multiply 0.5 |
| 3 | `shade` | `crease` | multiply 0.55 |
| 4 | `deep` | `outer` | multiply 0.6 |
| 5 | `accent` | `lid` | multiply 0.5 |
| 6 | `highlight` | `inner` | soft-light 0.6 |

- 칸 색이 하나도 승인되지 않은 팔레트는 지금처럼 `simulation-colors.csv`의 승인 메인 색 1개만 눈꺼풀 전체에 칠합니다(`MD-0034-01` = `#BF896D`).
- **현재 실제 데이터에서 승인된 팔레트 칸은 0개**입니다. 그래서 실제 화면에서 여러 칸 조합은 아직 나타나지 않으며, 10.4의 가상 팔레트 테스트로만 동작을 확인했습니다. 칸 색을 승인하면 코드 수정 없이 적용됩니다.
- 결과 화면의 팔레트 표에서 승인 전 칸은 "측정 참고색 (승인 전)"으로 표시합니다.

### 11.2 적용 방식 (`js/simulation.js`)

| 단계 | 내용 |

## 12. 무드별 아이섀도우 · 아이라인 · 공통 애교살 (2026-11-04)

### 12.1 원칙
- **LOVELY는 기존 눈꺼풀 로직(고정 연핑크)을 그대로 씁니다.** `EYE_STYLE`·`LINER_STYLE`에 lovely 키가 없어 기존 코드 경로를 탑니다.
- PURE~HIP은 승인된 팔레트 칸 색(`palette-colors.csv`)을 역할(base·mid·shade·point)별로 무드마다 다른 영역·불투명도로 칠합니다. 무드 설정은 색을 바꾸지 않습니다.
