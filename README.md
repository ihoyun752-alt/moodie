# Moodie (무디)

> 오늘의 나는, 이런 무드.

## 1. 프로젝트 소개

Moodie는 사용자의 **피부 특성, 퍼스널 컬러, 개인 취향**과 **오늘 원하는 메이크업 분위기**를 함께 고려해 어울리는 화장품을 추천하는 개인 맞춤형 뷰티·메이크업 추천 웹 서비스입니다.

사용자는 뷰티 프로필을 저장하고 7가지 메이크업 무드 중 오늘의 무드를 고릅니다. Moodie는 무드와 퍼스널 컬러, 피부 적합도를 바탕으로 카테고리별 제품을 추천하고, 사용자는 그중 원하는 제품을 **직접 선택**합니다. 선택한 제품의 색은 가상 얼굴 이미지에 입혀져, 결과 요약 화면에서 **메이크업 완성 모습**으로 확인할 수 있습니다.

핵심은 제품을 단순히 나열하는 것이 아니라, 원하는 분위기와 나의 뷰티 특성을 연결해 어울리는 제품을 발견하고 적용 결과까지 미리 보도록 돕는 것입니다.

## 2. 주요 기능

### 2-1. 뷰티 프로필 (`profile.html`)

| 항목 | 입력 방식 |
|---|---|
| 피부 타입 (필수) | 건성 · 중성 · 지성 · 복합성 · 민감성 중 1개 |
| 피부 고민 | 건조함 · 유분 · 모공 · 트러블 · 홍조 · 칙칙함 · 잔주름 중 최대 3개 |
| 퍼스널 컬러 | 봄 웜 · 여름 쿨 · 가을 웜 · 겨울 쿨(계절별 세부 유형 선택 가능) · 뉴트럴톤 · 아직 모르겠어요 |
| 선호 메이크업 스타일 | 7가지 무드 중 최대 3개 |
| 선호 마무리감 | 매트 · 세미매트 · 글로우 |

프로필은 로그인 없이 브라우저의 `localStorage`(`moodie.profile`)에만 저장되며 서버로 전송되지 않습니다. 마이페이지에서 확인·수정·삭제할 수 있습니다. Moodie는 퍼스널 컬러를 진단하지 않고, 사용자가 알고 있는 유형을 입력받습니다.

### 2-2. 오늘의 메이크업 무드 (`mood.html`)

| 무드 | 분위기 |
|---|---|
| PURE | 청순하고 맑은 피부, 은은한 생기 |
| NUDE | 자연스럽고 차분한 누디 톤 |
| MODERN | 정돈된 선과 세련된 분위기 |
| LOVELY | 화사한 혈색과 사랑스러운 눈매 |
| CHIC | 날렵한 눈매와 도시적인 분위기 |
| GLAM | 빛나는 눈가와 선명한 립 |
| HIP | 개성 있는 컬러와 그래픽 포인트 |

무드는 AI 메이크업 예시 이미지와 함께 제시되며, 고른 무드가 립·치크·아이섀도우 추천 기준과 결과 요약에 반영됩니다.

### 2-3. 개인 맞춤형 화장품 추천 (`recommend.html`, `js/recommend-engine.js`)

추천 대상은 **베이스 · 립 · 치크 · 아이섀도우** 4개 카테고리이며, 카테고리마다 따로 추천합니다. 점수는 아래 세 기준만으로 계산하는 규칙 기반 방식입니다.

| 평가 기준 | 배점 | 적용 카테고리 |
|---|---:|---|
| 메이크업 무드 적합도 | 40 | 립 · 치크 · 아이섀도우 |
| 퍼스널 컬러 적합도 | 30 | 4개 카테고리 모두 |
| 피부 적합도 | 30 | 베이스 |

- **립 · 치크 · 아이섀도우:** 무드 40 + 퍼스널 컬러 30 = 70점을 100점으로 환산합니다. 고른 무드가 제품의 대표 무드면 1.0, 보조 무드면 0.5를 반영하며, 대표 무드 제품이 항상 먼저 나옵니다. 무드가 맞지 않는 제품은 추천하지 않습니다.
- **베이스:** 무드와 관계없이 퍼스널 컬러 30 + 피부 30 = 60점을 100점으로 환산합니다. 피부 점수는 피부 타입 50%(추천 타입 1.0 · 해당 없음 0.5 · 주의 타입 0)와 피부 고민 일치 비율 50%입니다.
- **퍼스널 컬러:** 세부 유형 일치 1.0, 같은 계절 0.7, 다른 계절 0입니다. 제품에 퍼스널 컬러 근거가 없으면 이 항목을 점수에서 빼고 나머지 항목으로 환산하며, 따로 묶어 보여 줍니다. 뉴트럴톤 제품은 잘 맞는 제품이 3개 미만일 때 보완 추천으로 나옵니다.
- 사용자는 추천 카드에서 제품과 셰이드를 직접 고르고, 선택은 `localStorage`(`moodie.selection`)에 무드별로 저장됩니다.

고객 화면에는 브랜드, 제품명, 색상명, 색감 설명, 무드 추천 배지만 보입니다. 점수·계산 근거는 주소에 `?view=dev`를 붙인 개발 화면에서 확인할 수 있습니다.

### 2-4. 화장품 데이터 수집 및 관리 (`data/`)

판매처 자료가 아니라 접근 가능한 **각 브랜드 공식 홈페이지**를 중심으로 제품명·셰이드·가격·공식 문구를 조사했습니다. 현재 19개 브랜드, 34개 제품, 69개 셰이드(립 25 · 치크 12 · 베이스 19 · 아이섀도우 13)를 `data/products.csv`에 기록했습니다.

각 셰이드에는 브랜드·제품명·카테고리·셰이드명·가격·공식 주소, 대표·보조 무드, 퍼스널 컬러, 피부 타입·고민, 이미지 경로와 종류가 기록됩니다. 퍼스널 컬러와 피부 정보는 공식 문구로 확인한 값만 넣고 원문은 `data/evidence.csv`에, 무드 판단 기록은 `data/mood-tag-review.csv`에 보관합니다.

**색상 데이터 원칙:** 공식 홈페이지에서 HEX가 직접 제공된 제품은 현재 없어 `hex_color`는 비워 두었습니다. 얼굴에 칠하는 색은 출처를 구분해 따로 관리합니다.

- `swatch-measured`: 공식 상세 이미지의 발색 부분을 측정한 값 (립 6 · 치크 4 · 아이섀도우 1 셰이드)
- `ai-image-estimate`: 공식 근거가 없어 AI 제품 이미지에서 추정한 값(estimated). 공식 색이 아님을 기록하고, 고객 화면에는 색값을 표시하지 않음 (로지킴 립 10 레이스, 에이프릴스킨 히어로쿠션 19, 투에이엔 베러미 02 페어리 6칸)

실제 데이터의 검수 상태는 모두 '검수 전'입니다. 서비스 화면은 추천 흐름을 보여 주기 위해 시연용 검수 상태를 덧씌운 `data/products-demo.csv`를 기본으로 사용합니다. `?data=real`을 붙이면 원본 상태로 볼 수 있습니다.

### 2-5. 제품 이미지 제작 및 활용 (`assets/products/`)

저작권과 상표 문제를 고려해 브랜드 공식 사진이나 로고가 들어간 이미지를 그대로 쓰지 않고, 공식 페이지 등에서 확인한 패키지 형태와 발색을 참고해 **ChatGPT로 다시 생성한 이미지**를 사용합니다. 생성한 이미지는 육안으로 검수해 글자·로고가 없는 것만 쓰고, 브랜드·제품명은 화면의 HTML 텍스트로 보여 줍니다. 로고가 들어간 결과물은 새로 생성한 이미지로 교체했고, 로고처럼 보일 수 있는 장식은 문서에 따로 기록했습니다.

제품 카드마다 "AI 생성 이미지 · 실제 제품 사진 아님"을 표시하며, 이미지별 제작 방식·가공 내용·해시는 `docs/image-credits.md`에 기록했습니다.

### 2-6. 가상 메이크업 시뮬레이션 (`js/simulation.js`)

생성형 AI가 사용자의 셀카를 새로 만들어 내는 기능이 아닙니다. **미리 준비한 가상 얼굴 이미지 한 장**(`assets/simulation/base-face.png`) 위에, 선택한 제품의 색을 부위별 마스크로 브라우저 캔버스에서 합성합니다.

| 부위 | 마스크 | 합성 방식 |
|---|---|---|
| 베이스 | `skin` | 픽셀별 명암 비율을 유지한 채 피부 평균색만 제품 색 쪽으로 이동. 눈꺼풀·입술·배경은 제외하고, 경계는 안쪽으로 서서히 옅어짐 |
| 립 | `lip` | 입술의 주름과 명암을 살린 비율 합성. 매트 립스틱은 광을 줄이고, 틴트·밤·글로스는 반사광을 남김 |
| 치크 | `cheek-l`, `cheek-r` | 양 볼 그라데이션 마스크에 부드럽게 혼합 |
| 아이섀도우 | `eyelid-l/r`와 세부 영역 8개 | 팔레트 칸의 역할에 따라 눈두덩·음영 라인·눈꼬리·눈 앞머리에 나눠 칠함 |

베이스 → 치크 → 아이섀도우 → 립 순서로 겹쳐 여러 부위를 한 얼굴에 적용합니다. 승인된 시뮬레이션 색이 있는 제품만 칠하고, 색이 없는 제품은 "미리보기에 색이 표시되지 않아요"로 안내합니다. 얼굴 이미지는 해시로 확인해 바뀌면 합성하지 않습니다.

### 2-7. 결과 요약 (`result.html`)

결과 요약은 추천 목록을 다시 보여 주는 화면이 아니라, **사용자가 직접 고른 제품들이 함께 적용된 메이크업 결과**를 확인하는 화면입니다. 메이크업 전·후 얼굴, 부위별 확대, 오늘의 무드, 뷰티 프로필, 사용한 제품(브랜드·제품명·셰이드·색감 설명)을 함께 보여 주며, 여기서 제품을 다시 고르거나 다른 무드로 추천받을 수 있습니다.

## 3. 사용자 이용 흐름

```
메인 → 오늘의 무드 선택 → (저장된 프로필이 없으면) 뷰티 프로필 → 맞춤 제품 추천
     → 카테고리별 제품·셰이드 직접 선택 → 결과 요약(가상 메이크업 시뮬레이션)
```

메인에서 뷰티 프로필을 먼저 저장할 수도 있고, 프로필이 있으면 무드 선택 후 바로 추천으로 이동합니다. 메뉴는 MOOD · ALL(전체 제품) · 마이페이지입니다.

## 4. 기술 스택

- HTML, CSS, JavaScript (프레임워크·빌드 도구 없음), `localStorage` · `sessionStorage`
- CSV 기반 제품·색상·마스크 데이터, Canvas 2D 기반 마스크 합성
- 이미지 제작: ChatGPT 이미지 생성, Python Pillow(자르기·마스크)
- GitHub 저장소, GitHub Pages(배포 준비)

## 7. 현재 구현의 한계와 향후 개선 방향

**현재 한계**
- 공식 HEX가 확인된 제품이 없어, 얼굴에 칠할 수 있는 색은 13개 셰이드(측정 11 · 추정 2)와 팔레트 1종에 한정됩니다. 그 외 제품은 추천되더라도 미리보기에 색이 표시되지 않습니다.
- 베이스는 퍼스널 컬러 근거가 없어 피부 점수로만 정렬되고, 피부에 칠하는 색은 추정값 1개뿐입니다.
- 일부 무드·카테고리(예: HIP 립·아이섀도우, GLAM 아이섀도우)는 근거가 확인된 제품이 없어 추천이 비어 있습니다.
- 시뮬레이션은 가상 얼굴 한 장에 맞춘 마스크를 쓰며, 블러셔 모양이 원형에 가깝습니다.

**향후 개선 방향**
- 공식 색상 자료의 지속적인 수집·검증과 추정 색의 공식 색 대체
- 베이스 셰이드별 색상과 퍼스널 컬러 근거 확보
- 제품 데이터와 무드별 추천 범위 확대
- 다양한 피부톤·얼굴형 이미지와 자연스러운 색 합성(볼 형태, 질감 표현) 개선
- 생성형 AI 기반 시뮬레이션은 정확도와 저작권·초상권 검토 후 확장 가능성 검토

## 8. 실행 방법

CSV를 브라우저에서 읽기 때문에 파일을 더블클릭하지 말고 로컬 서버로 실행해야 합니다. Python 3과 최신 브라우저가 필요하고, 글꼴은 인터넷(Google Fonts, jsDelivr)에서 불러옵니다.

```sh
git clone https://github.com/ihoyun752-alt/moodie.git
cd moodie
python3 -m http.server 8001 --bind 127.0.0.1
```

브라우저에서 <http://localhost:8001> 을 엽니다. 서버는 반드시 저장소 폴더 안에서 실행하세요.

**GitHub Pages:** 모든 경로가 상대 경로라 `/moodie/` 하위 주소에서도 동작하는 것을 확인했습니다. 저장소 Settings → Pages에서 `main` 브랜치 `/ (root)`를 선택하면 배포됩니다. 아직 배포하지 않아 확인된 공개 주소는 없습니다.
